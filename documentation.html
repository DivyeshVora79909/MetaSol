1. Core Reactive Primitives (solid-js)

Hook Purpose Key Distinction
createSignal Creates a reactive state: [getter, setter] —
createEffect Runs a side effect that tracks dependencies and re‑runs when they change Does not return a value; purely for side effects (logging, DOM updates, localStorage)
createMemo Cached derived value; recalculates only when dependencies change Use for expensive computations; returns a signal
createResource Manages async data fetching; automatically re‑fetches when a source signal changes Returns a signal with loading, error, and data; differs from createEffect because it's stateful
createDeferred Delays updates until browser idle; keeps UI responsive Used for heavy lists or expensive renders
createSelector Optimizes list selection; creates a memoized comparison function Only updates the two items that change (selected/unselected), not the whole list
createRoot Creates a manual reactive owner outside components; returns a dispose function Used for global reactive code that needs explicit cleanup
Lifecycle hooks: onMount runs once after DOM mount; onCleanup runs before unmount or before effect re‑runs.

2. State Management & Context

  • createStore – makes a deeply reactive object (tracks nested changes). Signals can also hold objects, but they only track top‑level assignments.
  • createContext + useContext – dependency injection for passing data down the component tree without prop drilling. Values can be signals, stores, or plain objects.
  • batch – batches multiple updates to run effects only once. Used often in event handlers.
  • untrack – reads a signal without tracking it in the current effect/memo.

3. Rendering Utilities (solid-js/web)

Utility Purpose
render() Mounts a Solid app into a DOM container (client‑side only).
hydrate() Attaches reactivity to existing server‑rendered DOM (SSR).
<Dynamic> Component that renders a dynamically chosen component at runtime; useful for route switching or conditional rendering.

✅ <Dynamic> is just syntactic sugar for conditional rendering; it keeps lifecycle hooks clean.

4. Solid Router – Components

Component Purpose Key Props
<Router> Root provider for browser‑based routing (uses window.location) base, root (persistent layout), preload
<HashRouter> Router using #/path for static hosting same as <Router>
<Route> Defines a path and the component to render for that path path, component, children (nested), preload
<A> Enhanced anchor link for client‑side navigation href, activeClass, end, replace
<Navigate> Declarative redirect; renders immediately to navigate href, state
<Outlet> Placeholder for nested route content; also provides context prop to pass data to child routes context (object passed to child via useOutletContext)

5. Router Hooks (@solidjs/router)

📍 Location & Params

  • useLocation() – global signal of the current URL object
  • useParams() – returns only the params matched by this route (local scope)
  • useSearchParams() – reactive query string read/write
  • useMatch() – checks if a path matches the current route
  • useCurrentMatches() – array of all matched routes (top → bottom)

🧭 Navigation & Actions

  • useNavigate() – imperative navigation (the “setter”)
  • useBeforeLeave() – callback before leaving a route
  • useIsRouting() – signal indicating route transition
  • usePreloadRoute() – manually preload a route
  • useAction(), useSubmission() – manage form submissions

6. Scoping & Data Flow in Nested Routes

Golden Rule: The router is a tree for matching, but updates behave like a DAG – only affected parts re‑render.

❓ How to access parent params in a child?

  • Bad: Parse useLocation().pathname – brittle, causes over‑rendering.
  • Good (direct parent → child): Use <Outlet context={{ userId: params().id }} /> and useOutletContext() in the child.
  • Good (deep nesting): Use useCurrentMatches() to find an ancestor’s param, or use a global Context/Store.

🔄 What re‑renders / unmounts?

Change Parent Child
/users/1 → /users/2 (same route, different param) Stays mounted; re‑renders (param changed) Stays mounted; only updates if it reads the changed prop/context
/users/1 → /about (different route) Unmounts (destroyed) Unmounts (destroyed)
/users/1/posts → /users/1/posts/5 (child param changes) Stays mounted (no change) Stays mounted; re‑renders if it reads the param
Pragmatic rule: “Mounted = Tree, Updates = DAG”. Components are mounted/unmounted based on the route structure, not the parameter values.

📦 Outlet Context vs Global Context vs Props

Scenario Recommended Method Why
Parent → 1‑level child <Outlet context> + useOutletContext() Explicit, simple, respects DAG updates
Deep ancestor → descendant (2+ levels) useCurrentMatches() or custom hook Directly reads URL structure; no drilling
App‑wide data (e.g., logged‑in user) Global createContext or module store Decoupled from router, available everywhere
Prop drilling through multiple route layers ❌ Anti‑pattern Messy and defeats the purpose of nesting

7. How the Router Works (Under the Hood)

  • URL as a Signal: The router keeps the current URL in a global createSignal.
  • Matching: <Route> components form a tree; the router matches the URL against this tree.
  • Nested scope: Each <Route> creates its own useParams context – they are not merged. Child routes only see their own params.
  • Cleanup: When a route unmounts, all its effects, resources, and local signals are destroyed.
  • base prop: Strips a prefix from the URL before matching, making nested routing easier.
  • root prop: A layout component that persists across all route changes (never unmounts).

8. Quick Reference – Common Patterns

✅ Reading dynamic param

// In a route defined as /users/:id
const params = useParams();
const id = params().id;  // reactive

✅ Passing to immediate child

// Parent route
<Outlet context={{ userId: params().id }} />

// Child route
const { userId } = useOutletContext();

✅ Navigate imperatively

const navigate = useNavigate();
navigate('/profile', { replace: true });

✅ Access ancestor param (deep)

import { useCurrentMatches } from '@solidjs/router';

function useAncestorParam(name) {
  const matches = useCurrentMatches();
  for (const m of matches) {
    if (m.params[name]) return m.params[name];
  }
  return null;
}
⚠️ Watch out! useLocation() changes on any URL update (even query strings). Avoid reading it for param parsing to prevent unnecessary re‑renders.

9. Final Takeaways

  • Signals are the atomic unit; everything else builds on them.
  • Routes are a tree; updates are a DAG.
  • Props (or Outlet context) for parent→child; useCurrentMatches or global context for deeper access.
  • Dynamic is just a conditional wrapper; render/hydrate are for mounting.
  • Always keep lifecycle and cleanup in mind – when a route unmounts, so do its effects.
  • Documentation is your friend, but understanding the reactive model is the real superpower.
